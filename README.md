# DNUI 选课工具（Rust）

现有 Python/Tkinter 版本的独立 Rust 重构。功能包括：

- Rust 原生 ddddocr 验证码识别（内嵌 ONNX 模型，不依赖 Python/OpenCV）
- 登录、普通/实验轮次选择
- 从所选轮次页面动态识别 `FAWKC` / `TJKC` / `XGKC` 等课程类型
- 分页抓取、搜索过滤、仅显示可选课程
- 多选课程、定时开始、重复抢课、保活、暂停与停止

## 校园网与 VPN

校内请连接校园网。校外请先访问 [校园 VPN](https://vpn.neuedu.com)，选择“大连东软信息学院”，完成认证，并按学校提供的指引连接 VPN 客户端。

程序顶部提供“VPN 浏览器授权”“打开校园 VPN”和“检测校园网/VPN”入口。检测会请求真实选课验证码接口（不提交学号密码、不进行选课）；检测通过后再点击“登录并抓取本轮课程”。

### 浏览器能访问，但程序仍要求 VPN 验证

这不一定代表 aTrust 未连接：浏览器可能已有站点认证会话，而桌面程序没有。Windows 版可以尝试以下流程：

1. 点击“VPN 浏览器授权”，打开程序自己的独立 WebView2 授权窗口。
2. 在窗口内按学校要求完成 VPN 登录；如已在 aTrust 登录，仍可能需要在此窗口重新完成网页登录。
3. 点击窗口底部“返回选课页”，进入原始选课站点后点击“完成授权并检测”。
4. 程序只接收该授权窗口中适用于 `https://xk.neusoft.edu.cn` 的 Cookie，并用桌面 HTTP 客户端重新请求验证码接口。只有真实检测通过才显示成功，之后重新登录并抓取课程。

授权窗口需要 Microsoft Edge WebView2 Runtime。它使用独立的 InPrivate 会话，不读取 Chrome/Edge 等常用浏览器的账号密码或 Cookie 数据库。传递的站点 Cookie 只保存在本次运行的内存中，通过匿名管道传递，不写入偏好文件、日志、命令行或课程缓存；关闭程序后需要重新授权。WebView2 自身的运行数据目录位于 `%LOCALAPPDATA%\DNUI-XK\vpn-webview\`。

如果授权窗口完成认证后，桌面请求仍被要求验证，说明 Cookie 同步不足以接入该环境（例如存在应用级隧道策略），程序会明确报告检测失败，不会假装连接成功。此时需确认学校是否允许该桌面客户端接入，或使用校园网。程序不代替用户完成 VPN 登录、不重放临时网关验证链接、不绕过校园访问控制；桌面 API 请求仍禁止跨域跳转，普通选课接口自身的 401 仍按接口认证错误显示。

抢课或保活期间检测到 VPN 验证失效会停止任务。换课期间若已经提交退课请求后失去 VPN 访问，程序会提示手动核对 A、B 的实际选课状态，不会声称已经回选成功；重新连接后请先核对，再登录启动新任务。

学校外网访问要求参考：[教务部通知](https://jw.neusoft.edu.cn/2026_07/03_09/content-49988.html)。

## 构建

```powershell
cargo build --release
```

输出：`target\release\xk-rust.exe`

首次构建会下载 Rust ddddocr 依赖和 ONNX Runtime 静态库，因此耗时较长。

## 安全

偏好和课程缓存保存在 `%LOCALAPPDATA%\DNUI-XK\`，不会在可执行文件目录生成 JSON 文件。仓库不会复制 Python 版的账号、密码或课程缓存。
